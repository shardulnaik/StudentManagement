# Contributing

## Development Workflow

1. Create a feature, fix, refactor, or documentation branch from `develop`.
2. Make focused changes.
3. Test the changes locally.
4. Commit using a descriptive commit message.
5. Push the branch to GitHub.
6. Open a Pull Request against `develop`.
7. Address review feedback.
8. Merge only after required checks pass.

## Branch Naming

Use descriptive branch names:

- `feature/<description>`
- `fix/<description>`
- `refactor/<description>`
- `docs/<description>`
- `test/<description>`

## Commit Convention

Use descriptive conventional-style commits:

- `feat:` new functionality
- `fix:` bug fixes
- `refactor:` code restructuring
- `test:` tests
- `docs:` documentation
- `ci:` CI/CD changes
- `chore:` maintenance

Example:

`feat: add student search endpoint`

## Pull Requests

Pull Requests should:

- Explain the purpose of the change.
- Include relevant testing information.
- Avoid unrelated changes.
- Keep the scope focused.
- Update documentation when required.
